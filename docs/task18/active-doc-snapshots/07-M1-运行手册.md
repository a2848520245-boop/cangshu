# M1-运行手册

> **定稿权**：配置键与默认值、双模式运行、双轨部署、迁移执行、备份恢复、GC 与对账操作、告警出口、启动与退出码、健康检查与最小接口以本文件为唯一定稿处。数据模型见 [[06-M1-数据契约]]，锁与并发协议见 [[04-M1-架构与计划]]，接口见 [[05-M1-接口契约]]，门槛与证据见 [[08-M1-验收规范]]。
> **性质**：运行契约。只定义参数与操作步骤，不记录实现状态。全文 UTF-8。
> **命令说明**：本页出现的命令分两类——带来源的核对命令按原样适用；运行与部署命令**待交付环境重建后**方可在该环境执行，文中已逐条标注适用条件。不得把尚未重建的命令当作已存在能力。

## 1 配置键定稿

配置值来自统一绑定层，CLI 与 serve 不各自再写一套默认值。以下六个完整键名为定稿键名，补齐类型、单位、默认值与跨模式约束。

| 键名 | 类型 | 默认值 | 约束与说明 |
|---|---|---|---|
| `cangshu.data-root` | 文件路径 | `./var/data-root`（开发） | 启动解析并记录规范绝对路径；交付使用显式挂载路径 |
| `cangshu.upload.max-size` | DataSize | `2GB` | 明确大小单位及解析值；业务上限 |
| `cangshu.trash.retention` | Duration | `7d` | 允许测试值 `0`，禁止负数 |
| `cangshu.migration.dir` | 目录路径 | `./db/migration` | 启动确认可读及脚本集合 |
| `cangshu.migration.lock-key` | 64 位整数 | `20260918` | 协议值，登记在册 |
| `cangshu.writer.lock-key` | 64 位整数 | `20260919` | 协议值，登记在册，不再仅藏在代码默认值中 |

**环境变量映射（定稿）**：`cangshu.data-root` → `CANGSHU_DATA_ROOT`；`cangshu.upload.max-size` → `CANGSHU_UPLOAD_MAX_SIZE`；`cangshu.trash.retention` → `CANGSHU_TRASH_RETENTION`；`cangshu.migration.dir` → `CANGSHU_MIGRATION_DIR`。`cangshu.migration.lock-key` 与 `cangshu.writer.lock-key` 是协议常量，**不支持普通环境变量覆盖**（见锁键纪律）。HTTP 层的 multipart 限制（`max-file-size`／`max-request-size`）与业务上限同源；请求上限还需容纳协议开销，**不能把整个请求上限直接等同于文件字节上限**。

**锁键纪律**：`cangshu.migration.lock-key` 与 `cangshu.writer.lock-key` 按协议常量管理，**不支持普通环境变量或运行配置覆盖**，确需变更走协议变更流程。CLI、serve、人工迁移必须遵循同一锁协议；迁移操作需确保业务写者已退出。

**10GB 实验**：须显式提高业务与 HTTP 上传限制；2GB 是产品默认值，不构成实验上限。

**参数联动清单**：保留期、GC 周期（1 小时）、对账周期（1 日）、上传上限（默认 2GB）、数据根路径。

## 2 双模式运行

| 模式 | 形态 | 用途 |
|---|---|---|
| CLI 一次性作业 | 默认不启 HTTP 容器；以一次性作业入口按 `--mode=` 切换具体作业 | 迁移核对、GC、对账等后台作业 |
| serve | 覆盖为 servlet，启动 HTTP 容器 | 同源提供浏览器界面与八端点 |

Vue 3＋TypeScript＋Vite 构建产物置于 Spring Boot 静态资源并随 JAR 提供；UI 同源调用既有 API，不另起服务。CLI 与 serve 共用业务入口、配置、锁、数据根和迁移核对口径。

**健康检查与最小接口（定稿）**：健康检查＝Spring Boot Actuator `GET /actuator/health`；最小接口＝`GET /api/health`，返回 `status`／`service`／`config` 概要，形态遵循 [[05-M1-接口契约]] 总则（Base URL `/api`、JSON 字段 `camelCase`、UTF-8）。两者不属八端点契约。定稿依据：归档《仓鼠-M1-名词解释》Actuator 条目既定口径；2026-09-19 用户批准（ADR §十一 I9；[[10-变更记录]] 追加批次七）。

## 3 双轨部署

| 轨道 | 用途 | 数据库 | 字节存储 | 约束 |
|---|---|---|---|---|
| 开发态 | 日常开发与门槛实验 | 本机 PostgreSQL 17 服务 | 数据根目录 | 可用 `--mode=` 一次性作业切换；不改交付语义 |
| 交付态 | 他人按说明复现 | 容器内 PG 17，数据用 named volume | 独立 bind mount | 起库→人工按序跑当前迁移→构建JAR→起应用；禁空库降级 |

**两轨必须一致（不变量）**：① PG 大版本都为 17；② DDL 与迁移语义（脚本目录 ＋ 台账、人工执行、DDL 与记账同事务、脚本只增不改、应用不在启动时自动改表）；③ 内容键 `sha256/ab/cd/<digest>` 两轨一致；④ 配置语义一致，差异只在值与编排方式（环境变量 vs 配置文件）；⑤ 库初始化时固定排序规则，避免两轨中文排序不同。允许的差异只有容器／本机进程、卷／目录、变量注入方式；不允许的差异是表结构、状态取值、错误码、锁协议、内容键。

**命名口径**：PG named volume `cangshu-pgdata`；字节宿主目录 `cangshu-blobs`；容器内挂载点 `/data`。字节卷与 PG 卷必须分离——「换字节根」实验要求只动字节、不动数据库。PG 数据目录不得放 SMB／NFS 共享目录。

**首次初始化顺序（禁空库降级）**：

```text
1) 起 PG17 容器（独立卷、固定排序）
2) 按 §4 人工按序跑当前批准迁移（现 V1→V2）
3) 宿主 Node22/npm10 按 README `clean package` 构建 JAR；`compose up -d app`
4) 启动只读核对全量脚本／台账；不符退出码 3
```

「禁空库降级」＝不允许「库是空的就让应用自己建表」，也不允许「核对不过就跳过去继续跑」。

## 4 迁移操作

- 脚本目录 `db/migration/`（`V1__init.sql` …），脚本**只增不改**；已使用的迁移 SQL 继续只增不改。
- 人工持迁移锁执行；DDL 与记账同一事务，出错整体回滚。
- 应用不在启动时自动改表；启动只读核对版本集合、脚本摘要与关键结构（类型／非空／外键／唯一／索引、CHECK 与默认值），不符即退出码 3。
- 台账 `schema_version` 记版本、脚本名、执行时刻、脚本 SHA-256。
- 需要调整表约束时：先回灌数据模型裁决，再新增迁移脚本；不就地修订旧脚本。

## 5 备份与恢复

- **备份口径**＝PG 逻辑备份 ＋ 字节目录复制；**两者必须同批备份**，否则备份里的引用可能指不到字节。
- 备份恢复属门槛六的一部分：Compose 环境新验「初始化、重启、新卷恢复、更换字节根」四项，换根须复制字节、只改根配置、相对存储键不变。
- 大型数据、bundle 与数据库备份可留在外部稳定存储，但必须登记逻辑资产 ID、相对位置、摘要和恢复方法；外部原件丢失时，证据完整性检查必须失败。

## 5.1 事故预防操作规程（规范已批准；数值目标已裁决、独立落点待定）

**权限与执行入口。** 只读、验证、写入、备份上传和历史备份管理采用可核验的独立权限；普通 Agent／运行身份不得改历史备份、保留策略、可信允许根、计划或执行器。首版危险入口只支持 `PLAN_QUARANTINE` 与 `QUARANTINE_TREE`：版本化结构对象至少含 `schemaVersion`、`operation`、`rootId`、`target`、`runId`；执行另有 `planId`、`manifestSha256`、授权引用。未知／重复字段、类型错误、超限、重放均拒绝。可信注册表按 `rootId` 给出卷、目录对象身份、允许操作、隔离根、数量／字节限制与身份；调用者不能自报允许根。源码、Vault、备份、活数据、证据／staging 及其祖先不得登记为可丢弃根。字段不得拼成 shell 命令；具体权限承载与维护者**待决**。

**路径和计划。** 首版只接受已验证的本地 NTFS、大小写不敏感普通目录内完整盘符绝对路径；拒绝根／允许根本身／父级、相对或 drive-relative、穿越、UNC／设备／扩展命名空间、通配符、控制符、保留设备名、ADS、段末点／空格及不支持的别名／映射。按路径分量和卷／文件 ID 校验边界，大小写／8.3 别名按同一对象政策；源祖先、整个子树、隔离及目的路径任何 reparse point 均拒绝，普通文件多硬链接、特殊流或身份／读取不可确认也拒绝。合法文件名里的 shell 字符只能作字面量，绝不求值。计划由执行器重扫，列文件及空目录、相对路径、类型、对象 ID、文件大小／SHA、总数／上限、策略和执行器版本；稳定序列化后绑定摘要与具体授权，控制区由调用者不可修改。dry-run 不修改目标。执行前排空夹具写者并锁定源、祖先、目的父目录，重扫；须持续阻止核验至 rename 间的替换，失败即拒绝，不降级递归删除／复制。仅同卷、目标名不存在时整体 rename 入独立隔离根；先持久记 `PREPARED`，后核对对象／清单记 `QUARANTINED_VERIFIED`。崩溃或失败按对象身份只读判为 `NOT_MOVED`、`QUARANTINED_UNVERIFIED`、`STATE_UNKNOWN`；未知不自动重试／回滚。同 `runId` 只返回既有状态。隔离恢复须新计划、原位置不存在、边界重核且拒绝覆盖。隔离不等于备份；保留、容量、告警**待决**，空间不足停新操作，不自动删最老项。

**短期命令与服务。** 只管理执行器直接启动且确权的 Windows 短命令：暂停创建，配置 kill-on-close 且禁 breakaway 的 Job，纳入核验后才运行；失败终止未运行的自有进程。记录身份、字面参数、PID＋创建时间／句柄、版本、工作目录、期限、exit 与脱敏日志；Job 句柄不得泄漏。取消／超时先协作关闭、到限仅收束自有 Job；主命令 0、Job 空、业务断言及证据齐才成功。不能确权记 `PROCESS_TREE_UNVERIFIED` 并停自动重试。WMI／服务／任务计划／远端／既有 Docker、WSL daemon 代启不在首版支持范围。合成 VM 测试上限 10 秒、协作 5 秒、收束 5 秒仅为验收夹具；**生产命令的执行期限／宽限／收束期限待决**。PG 等长期服务按独立生命周期和实例身份、端口、干净停机证据管理；WinFR、其他任务及用户进程不附加、不终止、不因超时重跑。

**一致备份与恢复。** Git 在批准交付点推指定 ref 并读远端核对；另存完整 bundle 或有前置链的增量。工作单元结束、风险操作前及批准周期检查点短暂停写者，捕获 HEAD／refs／index、staged 与 unstaged 二进制差异、未跟踪及必要原始字节；登记删除、模式、摘要，核 submodule／LFS／必要 ignored 与排除项。捕获期有变化则重做。业务备份默认在同一停写窗口阻断 serve／CLI／GC／对账／迁移／脚本／人工写入、排空事务及文件句柄，再用运行中的 PG 执行 `pg_dump -Fc` 并复制／冻结字节，记录实例、版本、编码／locale、schema／ledger、角色／扩展恢复前提、行数／业务摘要、逐文件 SHA、必要有效内容及 tmp／orphan 状态清单；缺失／孤儿按既有契约分类，并核 DB→Location→字节关系；完成共同校验后才放行写者。失败不发布恢复点，保留旧有效代次，按维护流程恢复服务；超出可批准停写时长则另审在线一致性方案。上传须到独立物理／远端故障域，且当前 Agent 无历史代次覆盖／删除及改保留权；仅换盘符或同身份目录不合格。分别登记捕获、独立副本确认、实际恢复测试时刻；至少季度完整恢复演练及重要变化后增补。下述备份技术目标由用户委托 GPT-6 裁决；实际介质／身份、权限可行性及规模时限仍待取证，投用前不得声称可靠备份。PITR／WAL 后置，需更短 RPO 时另设计划。

**任务 33 无 AWS 修订（TASK33-NO-AWS-20260924）。** 用户确认没有 AWS 账号，原 AWS 双桶裁决只作为历史候选，不再是当前实施目标，也不要求为本任务开通。当前先在全新本地目录用合成数据作非破坏性模拟，核打包、manifest／SHA-256、读回、失败候选拒绝与合成恢复；同一台主机同一卷的目录不能算独立副本或真实权限隔离。正式落点仍须另有物理介质或独立远端，且普通 Agent／运行身份不能覆盖、删除历史或改保留；具体介质、管理者、身份、费用和权限承载待选。短期保留最近 14 天全部成功代次、每周另存一个完整代次并保留 8 周、至少两个独立确认有效代次，是待验证的设计目标；首版不授权普通 Agent 自动清理，清理只可先出计划。

**频率与时限目标。** Git 在工作单元结束、危险操作前及每 12 小时捕获完整本地状态；危险操作须等该检查点独立读回确认。PG 与字节根每 12 小时在同一停写窗口捕获，可选本地 02:00／14:00。单次最大停写目标 10 分钟，从阻断写入口到安全恢复写入计；第 8 分钟尚未完成应中止捕获并留安全退出时间，不可强行放开未核清的写者。共同一致状态在受保护本地暂存形成后即可恢复写入，再上传读回，不能因网络故障无限停写。捕获源参考时刻到独立副本确认目标 ≤1 小时。RPO 目标 ≤24 小时，按最近**已独立确认**恢复点的源参考时刻计龄；18 小时预警、24 小时判超标。RTO 目标 ≤4 小时，从源不可用起，计入发现、取得恢复身份、新实例、下载、恢复、校验和 HTTP 下载。漏跑／失败立即记录告警；频率和数值是设计目标，尚未由代表规模实测，不能宣称已达到。

**权限与确认。** 宿主采集拟用非管理员 Windows 身份及实际 NTFS ACL，PG 拟用独立备份角色；创建新代次、独立只读验证、历史管理须分离，当前 Agent／运行身份不得改历史、保留或独立确认回执。不可变机制和对象版本标识由最终介质决定，不假定本地文件夹或共用部署服务器具备这些能力。每代清单固定源参考时刻、资产范围、长度、SHA-256、位置及可读版本标识；独立身份读回指定代次后才形成确认。具体自然人、SID、PG 角色、维护取回、费用及告警接收点未登记。原 AWS 机制细节和官方依据保留在库外历史裁决记录，不作为当前实施指令。

**任务 33 的可行性关门。** `ACC-PREV-P` 须先登记真实独立目标、介质／服务身份、权限与管理者，并在合成夹具上实测普通身份对受保护历史的 OS／服务端拒绝、新代次创建、独立读回与确认；再以代表规模实测捕获、传输、恢复、容量和费用。原始日志绑定身份、策略摘要、当前 HEAD 与八文件基线。当前本地模拟只可证明流程局部，不给 `ACC-PREV-P` 或任务 35 的 `ACC-PREV-C` 判通过；任务 35 仍须按 §5 与 [[08-M1-验收规范]] 做断源和生产投用验证。

**私有 GitHub 先行备份（用户 2026-09-24 授权）。** 公开仓仍为主仓，沿用既有审查／发布；单一写入者在每个完整工作单元提交后，检查并推送代码分支／标签到新私仓，同时把仓鼠活文档和正式验收证据提交到同仓独立文档分支，核远端 ref 与清单摘要。未提交的中途状态可另作 D 盘安全快照，不冒充正式交付。所有参与模型遵守项目级入口规则并在交付前报告同步结果；规则不能保证未加载它的外部模型自动执行。私仓常规推送已获授权，无需逐次审批；不得因此自动推公开主仓。密钥／密码及原始恢复扫描件不入私仓；笔记只写密钥位置与取用方法，上传前按允许清单和敏感项检查。数据库逻辑备份与内容字节须先满足同一停写窗口的一致性要求，再作为同一私仓的 Release 附件，以 SHA-256 和对应代码／文档引用绑定；未取得成对有效包时仅标 `CODE_DOCS_ONLY`。每次有新工作单元即同步私仓，危险操作前先核可恢复点；首期不自动删除或覆盖历史代次，容量、频率、RPO、RTO、最大停写均按下述强目标继续实测。私仓管理员可改写历史，因此本阶段只降低本机误删损失，不等于 `ACC-PREV-P/C` 或任务 33／35 通过。

**异常删除。** 停新写任务，先收束确权自有运行单元；未知进程交有权者。源盘停写，最小卷／进程／命令证据写独立介质，由恢复负责人选择恢复路径并登记写入影响；应急演练只在隔离 VM 合成资源进行。所有验收判据见 [[08-M1-验收规范]] 的 `ACC-PREV-*`，本节不据步骤宣称通过。

## 6 GC、对账与告警

| 时机 | 动作 |
|---|---|
| 启动 | 完成对账后才允许开始服务 |
| 每小时 | 触发一次 GC（回收队列扫描）；GC 三段提交、每段独立提交，文件已缺可幂等完成 |
| 每日 | 触发一次对账（临时／孤儿／缺失三类） |

**即时告警触发条件**（不等到下一次每日对账）：① 同一对象连续两次每小时 GC 扫描后仍为 `RECLAIMING`（阈值＝2 个 GC 周期，本轮定稿的初始预算）；② 出现字节与内容地址不符（`BYTE_MISMATCH`）；③ 读路径发现缺失字节。第 ① 项在启动对账发现残留 `RECLAIMING` 行时即报告。`BYTE_MISMATCH` 必须**立即告警并停止删除**，字节不盲删。

**输出与出口**：对账命令输出结构化摘要；发现缺失字节、GC 字节不匹配等需要人工介入的故障时，以非零结果结束。serve 将同一事件写入结构化日志，并暴露最近一次作业结果。指标标签仅使用受控枚举，不用摘要或资源 ID 制造无限增长的指标序列。

**频率准确性**：保留期默认 **7 天**；等锁超 **30 秒**返回 503；冲突重试 **2 次**，退避 **50ms／100ms**；每小时 GC、每日对账。

## 7 启动与退出码

| 情形 | 行为 |
|---|---|
| 未拿到 DB 会话锁或数据根文件锁 | 停写，退出码 **2**，不写任何字节 |
| 迁移台账或结构只读核对不符 | 拒启，退出码 **3**，无降级开关 |
| 正常启动 | 完成对账后开始服务 |

## 8 发布前核对命令

以下命令用于核对证据与当前仓库的关系；`<代码仓>`、`<证据提交>`、`<交付提交>` 为占位符，执行时替换为实际值。

```text
git -C <代码仓> rev-parse HEAD
git -C <代码仓> status --porcelain=v1 --untracked-files=all
git -C <代码仓> show <证据提交>:<交付路径>
git -C <代码仓> ls-remote origin refs/heads/main
git -C <代码仓> merge-base --is-ancestor <证据提交> <交付提交>
```

最后一项只证明提交关系，不证明测试结果可沿用。`origin/main` 是本地缓存，远端核验记录必须带查询时刻。

**触发点固定为**：开始工作、提交验收、切分支或 reset 后、合并前、发布前。已知 HEAD、工作树或规范变更立即使相关核验过期；无法访问仓库就显示「不可观测」，不得沿用旧绿灯。

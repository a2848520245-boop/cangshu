# 开发宪章与治理

> **定稿权**：开发宪章、职责边界、SDD 流程、状态推导、引用与版本纪律以本页为唯一定稿处。范围与技术方向以 [[ADR-0001-项目启动与技术栈裁决]] 为准；实现与验收状态以 [[M1-任务表]] 为准。冲突裁决顺序：**ADR → 专题契约 → 任务验收映射 → 架构叙述 → 入口**。
> **性质**：本页只写规则，不写项目进度、不写实现状态、不复制 ADR 结论正文。全文中文、UTF-8。
> **授权口径**：本轮文档体系迁移按用户显式批量授权（清册整批）执行，**不新增权限门、不新增逐份确认、不降低既有约束**；需要确认的只有导师给出与既有裁决不同的约束这一种情形。

## 项目约束

- **交付形态**：导师按 FDE（端到端交付）带教——需求理解 → 产品识别 → 技术方案 → 开发 → 测试 → 交付 → 复盘，目的（成长与求职）与目标（项目完成度）分开（[[ADR-0001-项目启动与技术栈裁决]] §一、§十二）。
- **主栈与范围**：模块化单体 ＋ Java／Spring Boot ＋ PostgreSQL ＋ 本地内容寻址存储；M1 ＝ 单机、单用户、单文件最小闭环。纳入项与排除项只在 ADR §二 定稿，本页不复述。
- **四条不可重开口径**（不得作为新决策重开；再开条件＝导师给出不同约束并回写 ADR）：
  1. 删除只删引用（软删 → 引用归零 → 延迟回收）；
  2. MinIO 不直接使用，只作技术与思路参考；
  3. ORM 暂定 MyBatis-Plus（对比实验降为可选）；
  4. 哈希冲突按测试级验收（注入假摘要单测，不做现场演示脚本）。
- **开发方式**：强制 SDD——先文档后代码；不确定项收敛在文档阶段（导师 2026-09-15 分享要点，L1）。
- **质量约束**：每次发布执行全量回归并明确端到端覆盖；小步快跑（小迭代 → PR → CI → 合入）；门槛失败优先修数据模型、事务边界或存储协议，不得只靠换框架掩盖。
- **成本与边界**：超出价值的事可花钱或委托解决；不提前引入分布式基础设施（MQ／Redis／Go sidecar／K8s）。

**规范基线构成**：治理、ADR、SPEC、架构、API、数据、运行、验收八份构成 CI 只读输入的规范快照。**任务表、入口、变更记录、术语索引不参与基线计算**，避免「文档改文档、基线改基线」的循环。基线是只读输入，编辑权仍在 KB；修改必须回到 KB，再导出新基线。

## SDD 与迭代流程

```text
宪章 → SPEC → 澄清（AI 反向提问） → 计划 → 任务 → 实现
小迭代 → PR → CI（含风险评论） → 合入 → 发布（全量回归 ＋ 端到端覆盖）
```

- 每一环节沉淀 Markdown 并实时纠偏；原型先行（关键截图或对标站点 → 可交互原型 → 按原型实现 UI）。
- 人定：顶层框架、技术栈选型、重难点决策、最终验收；AI 做：实现与常规排查。
- 需求必须可定性定量，禁止「酷炫」这类无法验证的描述；上下文占用控制在 70% 以内。

## 状态与证据协议

**两组字段，不合并**：`安排`（待办／进行中／阻塞／后置）描述计划侧；`核验`（未验／通过／失败／待重验／不可观测）描述证据侧。**「完成」是派生条件，不允许自由填写。**

```text
完成 ⇔ 当前仓可观测
     且 工作区干净
     且 验收报告的 commit == 当前 HEAD
     且 验收报告的文档基线 == 当前批准基线
     且 必需验收项全部通过
     且 原始证据存在、摘要匹配
```

- 「已交付」比「通过」更强：还要求该提交已在指定远端交付分支或发布 tag 上得到核验；未 push 的本地成果可记通过，但不写「已交付」。
- 决策／文档任务绑定文档版本与裁决证据，不因代码回滚自动作废；实现任务在新 HEAD 或新基线出现后立即过期，旧报告转为历史证据，**不因祖先可达性沿用**。
- **核验触发点固定**：开始工作、提交验收、切分支或 reset 后、合并前、发布前。
- **不可观测处理**：静态 KB 无法自行察觉任意外部 reset。读取实时进度前必须刷新；无法访问仓库时就显示「不可观测」，不得沿用旧绿灯、不得推断完成。
- **证据包**至少含：`证据页.md`、`manifest.json`、结果明细、必要原始日志、必要快照或其可恢复定位信息。证据页写清：任务 ID、验收 ID、完整提交、文档基线、环境、命令、结果、失败项、SHA-256。
- 大型数据、bundle 与数据库备份可留在外部稳定存储，但必须登记逻辑资产 ID、相对位置、摘要与恢复方法；**外部原件丢失时证据完整性检查必须失败**。
- **规范变更以批次保存**：① 存修改前／后版本与摘要清单；② 在 [[10-变更记录]] 追加「原因—裁决 ID—受影响契约／任务—证据」；③ 同批修改规范、实现与测试映射；④ 收束报告记录**实际**偏离，不得用「计划已同步」代替实际检查。已使用的迁移 SQL 只增不改。

## 变更、引用与归档

- **稳定 ID**：`DEC-T*`／`DEC-I*`（裁决）、`REQ-M1-*`（需求）、`API-*`（接口）、`DATA-*`（数据）、`ACC-G*`／`ACC-HTTP`（验收）、`EV-日期-序号`（证据）。ID 一经使用不复用、不改义。
- **库内引用用块链接**：`[[ADR-0001-项目启动与技术栈裁决#^dec-t2]]`、`[[08-M1-验收规范#^acc-g4]]`；引用必须可解析，禁止只写裸文字 ID。
- **代码引用**：仓库 ID ＋ 完整提交 ＋ 相对路径；机器绝对路径只放在本机定位映射中。
- **归档边界**：归档件与旧报告只读、不就地改写、不重写归档说明；替代关系用新记录声明。
- **迁移前缀（本批）**：非归档旧源文件统一迁移到 `项目归档/文档版本/2026-09-19-体系迁移/原件/<原项目相对路径>`；**已有 `归档/` 下的原件保持原路径、原字节**。逐文件清册见 `migration-map.json`。
- **机械检查清单**（脚本可查，模型只做语义判断）：

| 检查 | 失败条件 |
|---|---|
| 文档清册 | 活文档超预算、文件遗漏、定稿职责重复 |
| 引用 | 双链／块 ID／证据 ID 不可解析；归档旧引用无迁移映射 |
| 状态 | 设计正文出现实施断言；入口复制状态或缺「不可观测」出口 |
| 任务 | ID 重复、原号被重排、验收无映射、依赖成环 |
| 计数 | 人工总数与按里程碑筛选结果不符；M2 任务混进 M1 分母 |
| 证据 | 提交或规范基线不匹配、工作树脏、报告缺失或摘要不符 |
| 契约 | 八端点、错误码、`reason`、状态枚举、配置键与测试清单不一致 |
| 门槛 | 六项门槛或故障矩阵缺项却标记发布通过 |
| 版本 | 规范变更无批次记录；受保护 SQL 或归档原件摘要变化 |

## 事故预防治理边界（2026-09-23 批准）

- 只读侦察／复核身份对输入只读；授权报告时仅另授明确输出区。会写夹具的构建、测试属于隔离验证任务。可写任务仅获分配工作树、夹具与输出区；Vault、活 DB／字节根、恢复原件、证据和历史备份不得因同盘或父目录授权被纳入。需核对删除子项及改 ACL／所有权权限。真实权限隔离不可由调用者改策略、计划或执行器，也不可经更高权限 shell／服务绕行；包装器拒绝不等于 OS 拒绝。宿主权限方案另由有权者配置取证，未建立前危险测试限隔离 VM。
- 危险文件操作每次需有对应授权；规范批准不批准具体删改。执行器首版只允许登记测试子树的只读计划与同卷整体隔离，未知操作及产品数据迁移／删除、永久清除、Git reset／clean、镜像同步不由它承接。产品软删、GC、孤儿隔离、迁移协议仍遵 [[ADR-0001-项目启动与技术栈裁决]]、[[04-M1-架构与计划]]，不被此流程改写。
- 操作证据按资产、来源、核验时点与缺失范围声明。原件字节／原始 Git 对象、原业务数据逻辑恢复、部分恢复、可读性候选、证据重建候选、结构重建、合成烟测、未验证／不可观测互不冒充；“完全恢复”须封闭资产清单和参考时点。进程运行、CPU、文件数量、全零占位、退出 0、构建成功均非恢复证明。此分类不新增任务状态枚举；[[M1-任务表]] 仍由现行证据规则推导。
- 异常根路径操作时先停止新写任务并收束已确权的自有运行单元；身份不明、其他任务、恢复扫描器不凭名称／旧 PID 终止。源盘停写后把最小证据写到独立介质，由恢复负责人选择映像、备份恢复或反删除并记录写入影响；不得边写源盘边声称保持未覆盖条件。操作细节见 [[07-M1-运行手册]]，验收见 [[08-M1-验收规范]]。
- 权限承载环境、独立备份落点／身份及数值目标投用前须有明确裁决和可行性证据；不得把批准规范或拟议任务记为控制已实施。模型审阅不冒充用户／导师裁决，除非用户明确委托其作该项技术裁决；旧证据不追改，新 HEAD／基线按既有规则复验。
